# Optional AWS infrastructure

**Nothing here is deployed.** There is no AWS account behind this repository, no
workflow can obtain credentials — `scripts/check_workflows.py` fails the build if one
tries — and `infrastructure/` exists to be synthesised, asserted against, and analysed
by the gate itself.

That last part is the interesting one. A cost tool that cannot price its own
infrastructure is a poor advertisement, and running the gate over this design found two
real defects while it was being written (see [What dogfooding found](#what-dogfooding-found)).

## What it would do

| Stack | Contains | Purpose |
|---|---|---|
| `CostGateStorage` | S3 bucket, DynamoDB table | Dated pricing snapshots, so a report can be reproduced later against the rates it used; prediction records, so an estimate can be compared against the bill (Phase 17). |
| `CostGateRefresh` | Lambda, EventBridge rule, log group | Refreshes the pricing catalog weekly. |
| `CostGateObservability` | SNS topic, CloudWatch alarm, AWS Budget | Alerts when the refresher fails or the spend approaches its limit. |

## What it would cost

Generated by the tool, not estimated by hand:

```bash
cost-gate analyze \
  --baseline tests/fixtures/empty-stacks \
  --proposed infrastructure/synthesized \
  --config infrastructure/cost-gate.yaml
```

| Resource | Dimension | Assumed usage | Monthly |
|---|---|---|---:|
| `Predictions` | Storage | 0.5 GB | $0.1250 |
| `RefreshLogs` | Ingestion | 0.1 GB | $0.0500 |
| `PricingSnapshots` | Storage | 1 GB | $0.0230 |
| `RefreshLogs` | Retained storage | 0.099 GB | $0.0030 |
| `Predictions` | Writes | 2,000 | $0.0025 |
| `RefreshCatalog` | Compute | 90 GB-seconds | $0.0015 |
| `Predictions` | Reads | 500 | $0.0001 |
| `PricingSnapshots` | Requests | 220 | $0.0002 |
| `RefreshFailed` | Alarm | high resolution | $0.1000 |
| **Total** | | | **$0.31** |

**Fixed cost: $0.10** — the alarm, which is charged whether or not it ever fires.
Everything else is per-request or per-gigabyte.

That figure used to read $0.00, and the test asserting it passed only because the alarm
was *unknown*. Pricing it honestly showed the claim had been flattering. What survives is
the narrower true statement: nothing here accrues in proportion to how long the system is
left running — no instance, gateway, cluster or database — and that is what
`tests/e2e/test_infrastructure.py` asserts now.

Three resource types are **not priced by this version** and appear as visible unknowns:
`AWS::Budgets::Budget`, `AWS::Events::Rule`, `AWS::SNS::Topic`. In practice they are
pennies — a budget is free for the first two — but the tool does not know that, and
saying so is better than guessing. Their absence means the $0.31 is a **lower bound**.

Prices come from the bundled fixture catalog and are illustrative, not authoritative.

## Design decisions

**Nothing is always-on.** No instance, NAT Gateway, load balancer, cluster or database.
`infrastructure/policies.yaml` blocks all five outright — a stricter rule than the
example policy set, because this system's entire premise is that it costs nothing at
idle, so introducing a standing charge would be a design error rather than a trade-off.

**On-demand, not provisioned.** The prediction table is written to roughly once per
analysed pull request. Provisioned capacity would be cheaper only far above that rate,
and would cost money while idle.

**Everything expires.** Snapshots move to infrequent access after 30 days and are
deleted after a year; noncurrent versions go after 30 days; incomplete multipart uploads
are aborted after 7. Log retention is one month. A log group left on "never expire" is
one of the commonest ways a serverless system acquires a bill nobody budgeted for.

**The refresher's permissions are boring.** It may call `pricing:GetProducts` and
`pricing:DescribeServices`, and write under one prefix of one bucket. It cannot delete a
snapshot — a refresher that can remove snapshots can destroy the audit trail it exists
to create — and it cannot read the prediction table at all.

**The Lambda code is inline.** Bundling needs Docker or esbuild, which would make
synthesis non-deterministic and stop the committed templates from being comparable. The
handler is a placeholder that raises; the real refresh logic is `cost-gate pricing
refresh`, which would be deployed as a layer.

## What dogfooding found

Running the gate over this design surfaced two genuine defects.

**The estimate was $53/month, almost all CloudWatch Logs.** The analysis had been run
under the payments application's *production* usage profile, which assumes 100 GB of log
ingestion. A Lambda that runs four times a month does not ingest 100 GB. The tool was
right; the configuration was wrong. Usage profiles are scoped by environment, so
pointing a second workload at another application's config gives you that application's
traffic assumptions applied to your resources. `infrastructure/usage.yaml` now describes
*this* system, and the estimate fell to $0.21 (later $0.31, once alarms were priced).

**Per-resource usage overrides silently did not apply to CDK resources.** Overrides are
keyed by logical ID, and CDK appends a hash of the construct path to every logical ID —
so an override written for `RefreshCatalog` never matched `RefreshCatalog6FFEA4AA`. The
author would see an unknown cost and no indication their configuration had been ignored.
Overrides now also match the construct path and the construct id, for the same reason
resources are paired on construct path (ADR 0004): the hash moves, the path does not.
An override that still matches nothing is now reported as a warning on the report,
because an override that never fires looks like a decision has been recorded when none
has.

## If you did deploy it

You would need an account, a CDK bootstrap, and a deliberate decision — none of which
this repository provides, and the last of which is the point.

```bash
pip install -e ".[cdk]"
npm install -g aws-cdk

cd infrastructure
cdk bootstrap aws://<account>/us-east-1
cdk deploy --all --context notificationEmail=you@example.com
```

Replace the placeholder account in `app.py` first; it is `000000000000` and always will
be in a committed file.

### Teardown

```bash
cd infrastructure
cdk destroy --all
```

**Two resources survive `cdk destroy` on purpose.** The bucket and the table carry
`RemovalPolicy.RETAIN`, because losing a pricing audit trail or a prediction history to
a mistyped command is worse than paying pennies to keep them. Remove them by hand when
you actually mean to:

```bash
aws s3 rm s3://<bucket> --recursive && aws s3 rb s3://<bucket>
aws dynamodb delete-table --table-name <table>
```

The log group is `RemovalPolicy.DESTROY` and goes with the stack. The budget and alarm
are deleted with `CostGateObservability`; check the AWS Budgets console afterwards,
since a budget deleted while a notification is in flight can leave the subscription
behind.

Regenerate the committed templates with `python scripts/dev.py synth`.
